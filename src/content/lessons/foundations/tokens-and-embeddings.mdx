A language model never sees letters or words. It sees a sequence of integers, and then it turns each integer into a vector. Both steps explain things you will run into in practice: odd costs, odd failures, and how search over documents works.

## Tokens

A **tokenizer** splits text into pieces called tokens and maps each piece to an integer ID. Most tokenizers are built with a **subword** method such as byte-pair encoding: common words become one token, rarer words are split into familiar parts, and anything unknown falls back to smaller pieces. That keeps the vocabulary at a manageable size while still being able to represent any text.

<TokenChips client:visible />

Three consequences follow.

- **Tokens are the unit of cost and capacity.** Prices are quoted per million tokens, and the context window is a token limit. For ordinary English, a token is roughly three quarters of a word, but that ratio is only a rule of thumb.
- **Not all text is equal.** Code, numbers, rare words and many non-English languages usually take more tokens per character than plain English, so the same content can cost more.
- **Models see pieces, not letters.** Questions such as counting the letters in a word are hard because the word may be one or two tokens. This is a tokenization effect, not a lack of intelligence.

## Embeddings

Each token ID is looked up in a table to get a vector, an **embedding**: a list of numbers, typically hundreds or thousands long. During training the model adjusts these vectors so that tokens used in similar ways end up near each other.

The same idea works on whole sentences and documents. A separate **embedding model** reads a piece of text and returns one vector for it. Texts with similar meaning land close together, which makes it possible to search by meaning rather than by keyword.

<EmbeddingSpace client:visible />

Closeness is usually measured with **cosine similarity**, the angle between two vectors, or with plain distance. To search a library you embed every document once, embed the question at query time, and return the nearest documents. That is the retrieval half of retrieval-augmented generation, which you will build in the RAG lesson.

## Things worth remembering

- Embeddings from different models live in different spaces. You cannot compare a vector from one model with a vector from another, and changing the embedding model means re-embedding everything.
- Similar does not mean relevant. Two passages can be close in meaning and still not answer the question, which is why retrieval quality needs its own measurement.
- Chunk size matters because one vector has to summarise the whole chunk.
