Read this sentence: "The animal didn't cross the street because it was too tired." What does "it" mean? You know it is the animal, not the street. A model has to work that out too. Attention is the trick that lets it. Every token (a small piece of text, often a word) looks at the other tokens and decides how much each one matters for its own meaning.

## A lookup, but soft

**Imagine this:** you are hungry, and you walk into a food street with ten stalls. You shout, "Something spicy!" Every stall hears you. The chaat stall waves hard. The biryani stall waves a bit. The ice-cream stall pretends it did not hear. That shout is the **query**: what you are looking for. Each stall's signboard is its **key**: what it offers. The food it hands you is the **value**. Here is the twist: a normal lookup picks one stall. Attention takes a little from every stall, and the stalls that matched best give the most. (Ice-cream still gets a tiny share. Nobody is perfect.) **In one line:** attention is a shout, ten signboards, and a plate that is mostly chaat.

For each token the model makes three vectors (lists of numbers) from what it currently knows about that token:

- a **query**: what this token is looking for
- a **key**: what this token offers to others
- a **value**: the information this token hands over when another token pays attention to it

A token's new representation is a weighted sum of every token's value. The weights come from comparing its query with every key.

## The same thing in code

```python
import numpy as np

def attention(Q, K, V, causal=True):
    # Q, K, V have shape (tokens, d)
    d = Q.shape[-1]
    scores = Q @ K.T / np.sqrt(d)                 # how well each query matches each key
    if causal:                                    # a token may not look at later tokens
        mask = np.triu(np.ones_like(scores), k=1).astype(bool)
        scores = np.where(mask, -np.inf, scores)
    weights = np.exp(scores - scores.max(axis=-1, keepdims=True))
    weights /= weights.sum(axis=-1, keepdims=True)  # softmax: each row sums to 1
    return weights @ V                            # blend the values
```

<Disclosure client:visible title="The formula">

The standard form is:

$$
\mathrm{Attention}(Q, K, V) = \mathrm{softmax}\!\left(\frac{Q K^{\top}}{\sqrt{d}}\right) V
$$

In words: compare every query with every key ($$QK^{\top}$$), shrink the scores, turn each row into weights that add up to 1 (softmax), and use those weights to blend the values. The shrinking step divides by the square root of the dimension $$d$$ (the length of each vector). Without it, scores grow as vectors get longer. That pushes the softmax into regions where gradients vanish, meaning the learning signal becomes too tiny to train on.

</Disclosure>

## What a full transformer adds

**Imagine this:** a class project where five friends read the same story. One checks the grammar, one tracks who is who, one watches the order of events. Then they pool notes. Real heads learn their jobs; nobody assigns them.

- **Many heads.** A head is one copy of attention. The model runs several at the same time, each with its own learned projections. So one head can follow grammar, another can follow who "it" refers to, and another can follow position.
- **Many layers.** Attention is followed by a small feed-forward network (a small neural network). This pair is stacked dozens of times. Early layers tend to capture local patterns and later layers more abstract ones.
- **A causal mask for generation.** When a model writes text, a token can only look at tokens before it. That is why generation is sequential: each new token depends on all the earlier ones.

## Why this matters for engineering

- **Cost grows with context.** Every token looks at every earlier token. So the work grows roughly with the square of the length. This is one reason long context is expensive and slow to first token.
- **Attention is what the KV cache stores.** While generating, the model keeps the keys and values of earlier tokens so it does not recompute them. That saved copy is the KV cache, the subject of the KV cache lesson.
- **Position in the prompt is not neutral.** Models often use information in the middle of a very long prompt less reliably than information at the start or end. So think about the order in which you place context.
