People often use "AI" and "machine learning" as if they mean the same thing. They also say generative AI, the kind that writes text and makes images, broke from everything before it. A better view is four steps. Each step kept the tools of the one before and changed how engineers spend their time.

## The four steps

**Imagine this:** a kitchen. First you write every recipe card yourself, one card per dish. Next, the cook learns the recipes by tasting. Then the cook reads every cookbook there is. Finally you stop cooking and run the restaurant. The four steps below follow that path, though real history was messier than any kitchen.

**Classical machine learning.** First you pick the **features**, the facts that describe each example (word counts for a spam filter, age and balance for a credit model). Then you train a small model, such as logistic regression or gradient-boosted trees, to turn those features into a label. One model does one task. You train it on labelled data you collected yourself.

**Deep learning.** Neural networks (models built from layers of simple connected units) learn the features themselves from raw pixels, audio or text. You stop crafting features by hand. Instead you manage bigger datasets, GPUs (chips that do many sums at once) and network designs, called architectures.

**Transformers and pretraining.** The transformer is one design that trains in parallel, meaning many parts at the same time, and keeps improving as it grows. You train a model once on a huge amount of unlabelled text. Its task is to predict the next token, a small piece of text. The result is a general-purpose asset, not a single-task model.

**The application era.** The model is now something you call, like a service. Your work moves to what surrounds it: prompts, retrieval, tools, evaluation, cost and safety.

In one line: each step kept the old tools and moved the effort somewhere new.

## What changed for engineers

| | Classical ML | Generative AI |
|---|---|---|
| Where the effort goes | Features, training, tuning | Prompts, retrieval, orchestration, evals |
| Output | A label or a number | Free text, different each time |
| Where cost lives | Training runs | Inference tokens, on every request |
| How you test | Accuracy on a held-out set | Eval suites, rubrics, judge models |
| Ownership | You own the model | You rent it, and the vendor can update it |
| Typical failure | A wrong prediction | A fluent, confident, wrong answer |

<Callout title="The old skills still matter">
Three skills still matter: checking that data is good, testing on examples the model has not seen, and noticing when real-world inputs drift away from what the model was trained on. They are the hard parts of generative AI too. People who learned them in classical machine learning tend to build more reliable systems than people who only know prompting. The [classical ML essentials](../classical-ml-essentials/) lesson covers them.
</Callout>

## What to take forward

- A model is a function trained on data. The newer ones are far more general, but what they were trained on still shapes them.
- Models improved because of scale, not only clever ideas. That is why the cost of training and serving became central.
- Most of the rest of this site is about the layers built on top: how a request is served, how knowledge is added, how quality is measured and what it all costs.
