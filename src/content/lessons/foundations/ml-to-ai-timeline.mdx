"AI" and "machine learning" are used as if they mean the same thing, and the generative AI of the last few years is often described as a break from everything before it. It is better understood as four steps, each of which kept the previous one's tools and changed what you spend your time on.

## The four steps

**Classical machine learning.** You decide which features describe the problem (word counts for a spam filter, age and balance for a credit model), then train a small model such as logistic regression or gradient-boosted trees to map features to a label. One model, one task, trained on labelled data you collected yourself.

**Deep learning.** Neural networks learn the features themselves from raw pixels, audio or text. You stop hand-crafting features and start managing larger datasets, GPUs and architectures.

**Transformers and pretraining.** One architecture that trains in parallel and scales. A model is trained once on a huge amount of unlabelled text by predicting the next token, and the result is a general-purpose asset rather than a single-task model.

**The application era.** The model is now something you call. Your work moves to prompts, retrieval, tools, evaluation, cost and safety around it.

## What changed for engineers

| | Classical ML | Generative AI |
|---|---|---|
| Where the effort goes | Features, training, tuning | Prompts, retrieval, orchestration, evals |
| Output | A label or a number | Free text, different each time |
| Where cost lives | Training runs | Inference tokens, on every request |
| How you test | Accuracy on a held-out set | Eval suites, rubrics, judge models |
| Ownership | You own the model | You rent it, and the vendor can update it |
| Typical failure | A wrong prediction | A fluent, confident, wrong answer |

<Callout title="The old skills still matter">
Checking that data is good, testing on examples the model has not seen, and noticing when real-world inputs drift away from what the model was trained on are the hard parts of generative AI too. People who learned them in classical machine learning tend to build more reliable systems than people who only know prompting. ## What to take forward

- A model is a function trained on data. The newer ones are far more general, but they are still shaped by what they were trained on.
- Capability improved as a result of scale, not only clever ideas, which is why the cost of training and serving became central.
- Most of the rest of this site is about the layers built on top: how a request is served, how knowledge is added, how quality is measured and what it all costs.
