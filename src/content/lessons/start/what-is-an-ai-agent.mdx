You can ask a chatbot for ideas on how to plan your week. But it cannot look at your calendar or book anything. It can only talk. An **AI agent** goes one step further: it can do things.

## A chatbot talks

A chatbot reads your message and writes words back. That is all it does. Ask what is on your timetable and it cannot look. It can only guess, or tell you how to find out.

## An agent can also do things

**Imagine this:** you ask a friend how to get to the shop, and they explain the route. That friend is a chatbot. Now you ask a friend to go to the shop for you, and they come back with the milk. That friend is an agent.

More exactly, an agent is a program that uses an AI model to work towards a goal. It can use **tools**: a search engine, a calendar, a calculator or another app. A tool is just something the agent can ask to do a job, like a pupil asking a teacher for a ruler.

Here are two everyday examples:

- A **homework planner** reads your timetable, sees a maths test on Friday, and adds revision slots to your calendar.
- A **travel helper** searches for trains, compares prices and puts the best choices in a list.

## The loop: think, act, look, repeat

**Imagine this:** a cook tastes the soup, decides it needs salt, adds some, and tastes again. Tasting and deciding is **think**, adding salt is **act**, and tasting again is **look**. An agent works in the same loop. (The cook stops when the soup is good. The agent stops when the job is done.) First it thinks about what to do next. Then it uses a tool. Then it looks at the result. Then it thinks again.

It stops when the job is done, or when it has run out of tries.

In one line: an agent is a model, some tools and a loop.

## Agents can make mistakes with real effects

**Imagine this:** you type a wrong word in a message and then press send. Now it is in everyone's pocket. Agents can press send for you. When a chatbot gets something wrong, you read a wrong answer. When an agent gets something wrong, something can actually happen. A message can be sent. A file can be deleted. Something can be bought.

Agents also only know what their tools show them. The calendar did not know about football. And an agent can make the same mistakes a chatbot makes, such as believing something false. Then it builds more steps on top of that mistake.

## So we give it limits

**Imagine this:** you give a younger cousin your phone for one game. You do not give them your bank app, and you say "ten minutes, then ask me". Builders do the same with agents, in four ways:

- **Few tools.** The agent can only use what it is given.
- **Small powers.** It might read a calendar but not delete it.
- **A step limit.** It stops after a set number of tries.
- **A person for important steps.** It asks before it sends, spends or deletes.

<Callout title="Rule of thumb">

If a step cannot be undone, or it affects other people, a person should say yes first.

</Callout>

## You are in charge

An agent is a helper, not a boss. If an app offers to do things for you, ask three questions. What can it do? What will it ask me before it does? How do I stop it? If you cannot find the answers, be careful.

<Deep title="Agents and workflows: the grown-up version">

Anthropic's engineers describe workflows as systems where models and tools follow "predefined code paths", and agents as systems where the model "dynamically" directs its own steps and tool use. They say agents are "typically just LLMs using tools based on environmental feedback in a loop". They also note that agents can cost more, that errors can build up over many steps, and they suggest testing in a sandbox, with stopping conditions and human checkpoints.
