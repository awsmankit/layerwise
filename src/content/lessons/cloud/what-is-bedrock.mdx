**Amazon Bedrock is AWS's managed service for using foundation models through an API.** You send a request, AWS runs the model on its own accelerators, and you pay for what you use. You do not provision GPUs, load weights or patch a serving stack.

<Callout title="One of three equal clouds" kind="note">
Bedrock is AWS's example of a managed model API. Microsoft Foundry and Google's Gemini Enterprise Agent Platform (formerly Vertex AI) do the same job under different names. See [The cloud AI map](../cloud-ai-service-map/) for a side-by-side translation, and [Choosing between AWS, Azure and Google AI platforms](../bedrock-sagemaker-foundry-vertex/) for how to decide.
</Callout>

If you know SageMaker, the contrast is useful. SageMaker is about building, training and hosting models that you control. Bedrock is about consuming models that already exist, from several providers, inside your AWS account's security and billing.

## How you pay

| Mode | How it works | Good for |
|---|---|---|
| On-demand | Pay per input and output token, no commitment | Getting started, spiky or unpredictable traffic |
| Provisioned throughput | Reserve capacity and pay by time | Steady, high volume where you need predictable latency, and for some customized models |
| Batch | Asynchronous jobs at a reduced rate | Bulk work that can wait |

Prompt caching and cross-region inference can also change your cost and availability. Prices vary by model and region, so work from the current pricing page rather than from memory, including this page.

## A first call

```python
import boto3

client = boto3.client("bedrock-runtime", region_name="us-east-1")

response = client.converse(
    modelId="<model id or inference profile from the console>",
    system=[{"text": "You are a concise technical assistant."}],
    messages=[{"role": "user", "content": [{"text": "Explain the KV cache in one paragraph."}]}],
    inferenceConfig={"maxTokens": 300, "temperature": 0.2},
)

print(response["output"]["message"]["content"][0]["text"])
print(response["usage"])   # input tokens, output tokens: this is what you are billed on
```

Switching models mostly means changing `modelId`, which is the main practical benefit of the Converse API. Behaviour, limits and prices still differ by model.

## Where it sits in the stack

In the stack on the home page, a managed model API such as Bedrock is the **platform** layer: it sits above inference engineering, which the cloud runs for you, and below your retrieval, agents and evals, some of which it also offers as managed pieces. Azure and Google Cloud have equivalent layers. The next lessons cover [Microsoft Foundry](../microsoft-foundry-and-azure-openai/), [Google's platform](../google-vertex-and-gemini-platform/) and [SageMaker](../sagemaker-and-hyperpod/), and [Choosing between AWS, Azure and Google AI platforms](../bedrock-sagemaker-foundry-vertex/) compares them.
