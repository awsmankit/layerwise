Google Cloud keeps its model access, training tools and agent tooling in one platform. For years that platform was called **Vertex AI**. On 22 April 2026, at Cloud Next, Google announced that Vertex AI is being succeeded by the **Gemini Enterprise Agent Platform**.

## What the rebrand means in practice

What Google states, as of October 2026:

- The Gemini Enterprise Agent Platform is "the evolution of Vertex AI", and Vertex AI services and roadmap will now be delivered through it rather than as a standalone service.
- A name-changes page lists the renames, for example Vertex AI Agent Engine became Agent Runtime and the Vertex AI API is now the Gemini Enterprise Agent Platform API.
- The `aiplatform.googleapis.com` endpoint still appears in Google's own release notes, but the Python SDK has a separate breaking change (2.0.1) that moves the agent surface out of `google-cloud-aiplatform`.
- Both names appear in documentation, consoles and invoices. Google's pages I read do not say whether existing customers must migrate, so check the notice for each service you use.

So in practice: search for both names, expect old tutorials and Terraform modules to say Vertex AI, and do not rewrite working code only because of the name, but do read the release notes for the SDK and for each service you depend on. The new name signals where Google is investing, which is agents. Check the current overview page for the exact scope.

<Callout title="Same pattern on other clouds" kind="note">
Microsoft did the same with Azure AI Foundry, which became Microsoft Foundry (announced November 2025). When a vendor renames a platform, check the API names, SDK package names and IAM role names before assuming anything changed. See [the service map](../cloud-ai-service-map/).
</Callout>

## Gemini API: on-demand versus provisioned

By default you share capacity with other customers and are billed per token. If you hit throttling at peak, or need steady latency, **Provisioned Throughput**, a fixed-cost, fixed-term subscription sized in generative AI scale units (GSUs), reserves a slice for you. The trade is the same as on every cloud: a commitment in return for predictability. Work out your steady baseline first, and let on-demand traffic handle spikes. See [Quotas, capacity and regions](../quotas-capacity-and-regions/).

## Agents on Google

Agent Runtime hosts agents. ADK is the code you write. You can write an agent in ADK and run it elsewhere, since ADK is open source, and you can also host agents built with other frameworks. Memory Bank and Sessions give an agent state across turns. For what an agent is and why loops need caps, see [Agents and tool use](../../rag-agents/agents-and-tool-use/).

## TPUs versus GPUs

Google offers its own chips, **TPUs**, next to NVIDIA GPUs.

- **GPUs** on Compute Engine are the familiar CUDA path. Families as of October 2026 include A4X Max (GB300), A4X (GB200), A4 (8x B200), A3 Ultra (H200), A3 Mega, High and Edge (H100), A2 (A100), G4 (RTX PRO 6000) and G2 (L4). A3 Ultra and A4 cannot be created as ordinary on-demand VMs: they need a capacity reservation, Spot or Flex-start. A4X and A4X Max need reserved capacity and do not support Spot or Flex-start.
- **TPUs** include v5e (cost-efficient), v5p, v6e (Trillium, generally available December 2024) and TPU7x (Ironwood), which entered preview on 24 November 2025 and became generally available on 31 March 2026. They run frameworks such as JAX, and PyTorch support exists but check the current docs for your model.

A rough rule: if your team already depends on CUDA libraries or custom kernels, use GPUs. If you train or serve large models on frameworks with good TPU support, and the price-performance matters, evaluate TPUs. Measure both on your workload, because vendor figures do not transfer.

<Deep title="Why accelerator choice affects portability">
CUDA code does not run on a TPU, and Trainium and Inferentia on AWS need the Neuron SDK. A managed model API hides all of this. The moment you serve your own model on a custom chip, you take on a compiler, a framework version and a library ecosystem that is specific to that chip. The savings can be real, but treat the porting work as part of the cost.
</Deep>

## Data handling

Google says it will not use your data to train or fine-tune models without your prior permission or instruction, per its zero-data-retention page opened on 28 October 2026. The page also says published Gemini models cache customer data by default to reduce latency (you can turn caching off per project), that prompts may be logged for abuse monitoring for customers on the standard Google Cloud terms, and that the global endpoint can serve requests from any region, so read it for your contract. More in [Security and networking for AI](../cloud-security-and-networking-for-ai/).

## What to take forward

- Vertex AI is now part of the Gemini Enterprise Agent Platform. Expect both names, and read each service's notice.
- Idle Vector Search nodes and provisioned capacity keep billing.
- A3 Ultra and A4 GPUs need reservations, Spot or Flex-start.
- Choose TPUs only after checking framework support and measuring your workload.
